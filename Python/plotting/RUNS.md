# 실험 실행과 그림의 대응 관계

논문에 들어가는 그림이 각각 어떤 학습 실행에서 나왔고, 그 실행이 어떤 설정이었는지
정리해 둔다.

실행 이름만으로는 어떤 신경망 구조로 돌렸는지 알 수 없는 경우가 있다. 실험을 여러
차례 나눠 돌리면서 이름을 붙였기 때문에, 이름과 설정이 항상 맞아떨어지지는 않는다.
그래서 아래 표의 구조 열은 스크립트를 읽어서 적은 것이 아니라, 저장된 체크포인트를
직접 열어 확인한 값이다. 전문가들의 레이더 인식부가 같은 텐서를 가리키면 공유,
다르면 분리로 판정했고, 폭은 합성곱 채널 수로 구분했다.

---

## 1. 공통 설정

그림에 쓰인 모든 학습이 아래 값을 똑같이 사용했다. 실행마다 달라지는 값만 3절 표에
따로 적었다.

```
--envs 128 --vessels 16 --rollout 32 --steps 16000000 --ring 0.7
--comm_on_at 9000000            전체 16M 중 9M 지점부터 통신을 켠다
--max_partners 4                메시지를 받는 이웃 수
VESSEL_MSG_DIM=6                메시지 벡터 길이
VESSEL_RADAR_RANGE=56           레이더 탐지 거리(m)
VESSEL_THREAT_COEF=0.5          원거리 위협 보상 계수
VESSEL_SIM_COLREGS_COEF=0.45    규정 준수 보상 계수
VESSEL_POS_GROUND=1             메시지에 송신자의 상대 위치를 함께 실어 보낸다
VESSEL_USE_ATTENTION=0          이웃 메시지 집계는 어텐션이 아니라 마스크 평균
```

시드는 42, 43, 44 세 개를 사용했다. 실행 이름 끝의 `_s43`, `_s44`가 시드를 가리키고,
접미사가 없는 것은 시드 42다.

## 2. 신경망 구조 네 가지

COLREGs 조우 상황은 다섯 가지(조우 없음, 정면, 교차 침로유지, 교차 양보, 추월)다.
상황을 선박 간 기하로 판정한 뒤 그 값으로 담당 전문가에게 곧바로 보낸다. 어느
전문가에게 보낼지를 학습하지 않으므로, 한 전문가로 쏠려 나머지가 죽는 문제가 없고
어떤 전문가가 무엇을 맡는지도 사람이 읽을 수 있다.

네 구조의 차이는 이 다섯 갈래를 신경망의 어디까지 적용하느냐다.

| 구조 | 환경변수 | 레이더 인식부 | 판단부 | 파라미터 |
|---|---|---|---|---|
| 단일망 | `VESSEL_USE_MOE=0` | 1벌 | 1벌 | 369,131 |
| 분리·얇게 | `USE_MOE=1 MOE_WIDTH=0.44` | 5벌(얇게) | 5벌 | 363,004 |
| 분리·두껍게 | `USE_MOE=1 MOE_WIDTH=1.0` | 5벌 | 5벌 | 1,826,719 |
| 공유(제안) | 위에 `MOE_SHARED=1` 추가 | **1벌** | 5벌 | 511,543 |

레이더 인식부가 신경망 전체의 89%를 차지한다(369,131개 중 328,794개). 분리·두껍게가
5배로 불어나는 이유는 이 무거운 부분을 다섯 벌 복제하기 때문이고, 공유형이 1.39배에
그치는 이유는 이 부분을 한 벌만 두기 때문이다. 늘어난 것은 판단부(40,337 → 182,749)
뿐이다.

## 3. 그림별 대응

### Fig1 통신 유무

| 조건 | 실행 | 구조 | 차이점 |
|---|---|---|---|
| 통신 없음 | `qf_SE_OFF_s42/s43/s44` | 공유(제안) | `--arm OFF` |
| 통신 있음 | `qd_MOE_SE_s42/s43/s44` | 공유(제안) | `--arm ON` |

`--arm OFF`는 메시지 입력을 항상 0으로 넣는다. 두 조건의 차이는 통신 하나뿐이다.

### Fig2 신경망 구조

| 조건 | 실행 | 구조 | 시드 |
|---|---|---|---|
| Single network (369K) | `q_MOE_SINGLE`, `qd_MOE_SINGLE_s43/s44` | 단일망 | 3 |
| Separate experts, thin (363K) | `q_MOE_ISO` | 분리·얇게 | 1 |
| Separate experts, full (1.83M) | `base_comm`, `base_comm_s43/s44` | 분리·두껍게 | 3 |
| Shared perception (512K) | `qd_MOE_SE_s42/s43/s44` | 공유(제안) | 3 |

네 조건 모두 메시지 6차원, 통신 9M 시작, 이웃 4척으로 같고 구조만 다르다. 특히
`base_comm`과 `qd_MOE_SE`는 레이더 인식부 공유 여부 하나만 다른 대응쌍이다.

thin 조건은 시드가 하나뿐이고 도착률 33.8%로 혼자 크게 무너져 있다. 시드를 보강하거나
이 조건을 빼는 판단이 필요하다.

### Fig3 메시지 집계

| 조건 | 실행 | 구조 | 차이점 |
|---|---|---|---|
| Nearest-1 | `qf_SE_NEAR1_s42/s43/s44` | 공유(제안) | `--max_partners 1` |
| Aggregation of 4 | `qd_MOE_SE_s42/s43/s44` | 공유(제안) | `--max_partners 4` |

### Fig4 메시지 차원

| 조건 | 실행 | 구조 |
|---|---|---|
| Dimension 2 | `v2_DIM2`, `q_DIM2_s43/s44` | 분리·두껍게 |
| Dimension 4 | `v2_DIM4`, `qe_DIM4_s43/s44` | 분리·두껍게 |
| Dimension 6 | `base_comm`, `base_comm_s43/s44` | 분리·두껍게 |
| Dimension 8 | `v2_DIM8`, `qe_DIM8_s43/s44` | 분리·두껍게 |
| Dimension 10 | `v2_DIM10`, `qh_DIM10_s43/s44` | 분리·두껍게 |
| Dimension 12 | `v2_DIM12`, `q_DIM12_s43/s44` | 분리·두껍게 |

`VESSEL_MSG_DIM`만 다르다. 이 축은 제안 구조가 아니라 분리·두껍게 위에서 측정했다.
여섯 조건이 서로 같은 구조이므로 축 안의 비교는 유효하지만, "모든 절제 실험을 제안
구조에서 수행했다"고 서술할 수는 없다. 제안 구조로 옮기려면 15회를 다시 학습해야
한다.

| 조건 | 실행 | 구조 | 차이점 |

완료되면 항 있음 조건을 `qd_MOE_SE`로 교체해 이 축도 제안 구조로 통일한다.

## 4. 이름 때문에 혼동하기 쉬운 세 가지

`base_comm`은 이름과 달리 기준선이 아니라 분리·두껍게 구조다. Fig4와 Fig5가 제안
구조 위에서 측정되지 않은 이유가 여기에 있고, 동시에 Fig2에 5배 조건을 추가 학습 없이
넣을 수 있었던 이유이기도 하다.

`q_MOE_ISO`의 ISO는 isolated가 아니라 iso-parameter, 즉 단일망과 파라미터 수를 맞췄다는
뜻이다. 폭 0.44짜리 얇은 쪽이며 5배 조건이 아니다.

실행 이름의 접두사(`q_`, `qd_`, `qe_`, `qf_`, `qh_`, `v2_`)는 몇 번째 실험 묶음에서
돌렸는지를 나타낼 뿐 설정과는 무관하다. 구조를 확인할 때는 이름이 아니라 체크포인트를
열어 볼 것.

## 5. 성능 값의 측정 방법

막대 그림의 값은 학습 로그가 아니라, 학습이 끝난 뒤 정책을 고정하고 다시 항해시켜
얻은 것이다. 학습 중의 기록은 에피소드가 한꺼번에 끝나는 시점에 따라 창마다 크게
흔들리므로 최종 성능 판단에 쓰지 않았다.

```
python eval_ckpt.py --ckpt <체크포인트> --arm ON --max_partners 4 \
       --envs 96 --burnin 1500 --eval_decisions 3500
```

`--burnin 1500`은 집계하지 않고 먼저 돌리는 구간이다. 모든 선박이 같은 시점에
출발하면 종료도 함께 몰려 통계가 왜곡되므로, 위상을 흩뜨린 뒤부터 집계한다.

결과는 `_data/metrics_v2.txt`(전체 지표)와 `_data/metrics_sit.txt`(상황별 준수율)에
한 줄씩 누적된다.

## 6. 학습 곡선의 세로축

로그에 찍히는 `R` 값이 아니라, 같은 로그의 결과 분포로 다시 계산한 값이다.

```
보상 = 1.5 × 도착 − 6.0 × 충돌 − 0.5 × 시간초과      (창별 종료 에피소드 수로 가중)
```

로그의 `R`은 매 결정마다 주는 유도 보상의 평균이라 도착이나 충돌 같은 최종 결과와
상관이 낮다(실측 상관계수 약 0.02). 이 값을 그대로 그리면 성능 그림과 학습 곡선이
서로 다른 이야기를 하게 된다. 위 식은 모든 조건에 동일하게 적용하며, 충돌 가중치를
3배에서 15배까지 바꿔도 조건 간 순서는 변하지 않는다.

## 7. 그림을 만드는 코드

| 파일 | 산출물 |
|---|---|
| `make_ablation_rewards.py` | `20_REWARD/` 학습 곡선 |
| `build_final.py` | `99_FINAL/` 주제별 폴더(곡선 1장 + 지표 막대 + 설명) |
| `make_mixed_fleet.py` | 혼합 함대 묶음 막대 |
| `regenerate_all.py` | 위 과정을 순서대로 실행 |

모든 스크립트는 `Figures/_data/`에 복사해 둔 로그만 읽는다. 값을 수정하는 코드는 없다.

```
cd Figures
python regenerate_all.py
python build_final.py
```

`_data/`에 로그를 얼려 두었으므로 다른 폴더가 지워져도 그림을 그대로 다시 만들 수 있다.
