# 그림 ↔ 실행 ↔ 설정 정리

논문 그림이 각각 어떤 학습에서 나왔고 그때 뭘 어떻게 줬는지 매칭해둠.

실행 이름만 봐서는 구조를 알 수 없음. 실험을 여러 번 나눠 돌리면서 이름을 붙여서
이름과 설정이 안 맞는 경우가 있음. 그래서 아래 표의 "구조" 열은 스크립트 읽고 적은 게
아니라 **체크포인트를 직접 열어서 확인한 값**임.
(전문가들 레이더 인식부가 같은 텐서를 가리키면 공유, 다르면 분리. 폭은 conv 채널 수로 판정)

## 0. 헷갈리기 쉬운 3가지 — 이것부터

**`base_comm`은 기준선 맞음. 다만 제안 구조가 아님.**
`baseline.sh`로 돌린 통신 ON 기준 실행이고, Fig4의 dim6 팔이자 Fig5의 "규정항 있음" 팔임.
헷갈리는 지점은 이 기준선이 **분리·두껍게(1.83M)로 학습됐다**는 것. 공유형(제안) 아님.
→ Fig4·Fig5가 제안 구조 위에서 측정된 게 아닌 이유임.

**`q_MOE_ISO`의 ISO는 isolated 아님.** iso-parameter, 즉 단일망과 파라미터 수를 맞췄다는 뜻임.
폭 0.44짜리 얇은 쪽이고 5배 조건 아님.

**접두사는 아무 의미 없음.** `q_ qd_ qe_ qf_ qh_ ql_ qo_ v2_` 는 몇 번째 실험 묶음에서
돌렸는지 표시일 뿐 설정과 무관함. 구조 확인할 땐 이름 말고 체크포인트를 볼 것.

**곡선은 15M까지만 그림.** 학습은 16.06M까지 돌았는데 그림 상한은 `VESSEL_FIG_XMAX=15000000`임.
`regenerate_all.py`가 이 값을 넣어주므로 **`make_ablation_rewards.py`를 맨손으로 돌리면 안 됨**
(16M까지 그려져서 Fig1 두 팔의 끝점 순서가 뒤집힘). 재생성은 반드시 6절 절차대로 할 것.

## 1. 공통 설정 — 그림에 쓴 전 실행 동일

```
--envs 128 --vessels 16 --rollout 32 --steps 16000000 --ring 0.7
--comm_on_at 9000000            16M 중 9M 지점부터 통신 켬
--max_partners 4                메시지 받는 이웃 수
VESSEL_MSG_DIM=6                메시지 길이
VESSEL_RADAR_RANGE=56           레이더 거리(m)
VESSEL_THREAT_COEF=0.5          원거리 위협 보상
VESSEL_SIM_COLREGS_COEF=0.45    규정 준수 보상
VESSEL_POS_GROUND=1             메시지에 송신자 상대위치 같이 실음
VESSEL_USE_ATTENTION=0          이웃 메시지 집계는 마스크 평균
```

시드 42 / 43 / 44 세 개 씀. 이름 끝 `_s43` = 시드 43. 접미사 없으면 시드 42임.

위 표는 **각 축이 자기가 건드리는 값 하나만 바꾸고 나머지는 그대로**라는 뜻임. 예를 들어
Fig3은 `--max_partners`만, Fig4는 `VESSEL_MSG_DIM`만, Fig6은 `--comm_on_at`만 다름.

## 2. 구조 4종

COLREGs 상황 5개(조우없음 / 정면 / 교차유지 / 교차양보 / 추월)를 선박 간 기하로 판정해서
담당 전문가한테 바로 보냄. 어디로 보낼지를 학습하지 않으므로 한 전문가로 쏠려서 나머지가
죽는 문제 없음.

4종의 차이는 **이 5갈래를 신경망 어디까지 적용하냐**임.

| 구조 | 환경변수 | 인식부(눈) | 판단부 | 파라미터 |
|---|---|---|---|---|
| 단일망 | `USE_MOE=0` | 1벌 | 1벌 | 369,131 |
| 분리·얇게 | `USE_MOE=1 MOE_WIDTH=0.44` | 5벌(얇게) | 5벌 | 363,004 |
| 분리·두껍게 | `USE_MOE=1 MOE_WIDTH=1.0` | 5벌 | 5벌 | 1,826,719 |
| **공유(제안)** | 위 + `MOE_SHARED=1` | **1벌** | 5벌 | **511,543** |

레이더 인식부가 신경망의 **89%**(369,131 중 328,794). 분리형이 5배로 뛰는 게 이 무거운 걸
5벌 복제해서임. 공유형은 이걸 1벌만 두고 판단부만 5벌 → 늘어난 건 40,337 → 182,749뿐임.

### 어느 브랜치가 어느 구조냐

저장소: `DragonTrainerTristana/DT_Vessel` · git root 는 `Assets/Scripts/` 임.
브랜치마다 `Python/config.py` 의 **기본값**이 달라서, env 를 아무것도 안 주고 학습을 돌리면
그 브랜치의 구조로 학습됨. 아래는 config.py 를 직접 읽어 확인한 값임.

| 브랜치 | `USE_MOE` | `MOE_WIDTH` | `MOE_SHARED` | 무설정 학습 시 구조 |
|---|---|---|---|---|
| `main` | 1 | 1.0 | 0 | 분리·두껍게 1.83M |
| `Thick_MoE` | 1 | 1.0 | 0 | 분리·두껍게 1.83M |
| `Light_MoE` | 1 | **0.44** | 0 | 분리·얇게 363K |
| **`Shared_MoE`** | 1 | 1.0 | **1** | **공유(제안) 512K** |
| `msgComparision` | 1 | 1.0 | 0 | 분리·두껍게 1.83M |

**`Shared_MoE` 만 공유형임.** 나머지 넷은 전부 분리형이고, `Light_MoE` 만 폭이 좁음.
`main` `Thick_MoE` `msgComparision` 은 구조 기본값이 서로 같음(용도만 다름).

**단일망은 전용 브랜치가 없음.** 아무 브랜치에서나 `VESSEL_USE_MOE=0` 을 주면 됨.

⚠️ **위 표는 "이 구조를 재현하려면 어느 브랜치를 쓰면 되는가"임.** 과거 실행이 실제로 어느
브랜치에서 돌았는지는 로그에 안 남아서 확인 불가임. 다만 구조 자체는 체크포인트를 열어
확인했으므로(2절), 재현에는 문제 없음. env 를 명시해서 돌리면 브랜치와 무관하게 같은 구조가 나옴.

원격의 `archive/*` (`Comm_BaseLine` `Comm_COLREGsReinforcement` `Comm_MoE`
`Comm_msgComparison` `NonComm_BaseLine`) 는 이전 세대라 지금 그림과 무관함.

**그림 파이프라인은 다섯 브랜치 전부에 있음**(`Python/plotting/`, `eval_mixed.py`).
다만 **이 문서(RUNS.md)는 `msgComparision` 에만 있음** — 나머지 넷에도 복사해야 함.

## 4. 성능 값은 어떻게 쟀나

막대 그림 값은 학습 로그가 아님. **학습 끝나고 정책 고정한 뒤 다시 항해시켜서** 잰 값임.
학습 중 로그는 에피소드가 한꺼번에 끝나는 타이밍 때문에 창마다 심하게 흔들려서 안 씀.

```
python eval_ckpt.py --ckpt <ckpt> --arm ON --max_partners 4 \
       --envs 96 --burnin 1500 --eval_decisions 3500
```

`--burnin 1500` = 집계 안 하고 먼저 돌리는 구간. 전부 같은 시점에 출발하면 종료도 몰려서
통계가 깨지므로 위상 흩뜨린 다음부터 셈.

결과는 `_data/metrics_v2.txt`(전체 지표), `_data/metrics_sit.txt`(상황별 준수율)에 한 줄씩 쌓임.
같은 태그가 여러 번 있으면 **뒤에 붙은 줄이 이김**(로더가 덮어씀). 새 결과는 끝에 붙일 것.

Fig7·Fig8만 다른 스크립트를 씀. 비율 7가지를 환경마다 다르게 심어 **한 번에** 재는 구조라
7번 따로 돌리는 것보다 빠르고 burn-in도 한 번만 냄.

```
python eval_mixed.py --ckpt qd_MOE_SE_s42.pt --mode radar --tag s42 \
       --envs_per 14 --burnin 1200 --eval_decisions 4500 --csv mixed_fleet.csv
```

`--mode rx` 로 한 번 더, 시드마다 반복. 결과는 `_data/mixed_fleet.csv`에 이어 쌓임
(헤더는 파일이 없을 때만 씀). 체크포인트는 `VESSEL_CKPT_DIR` 에서 찾음.

**막대 그림과 곡선의 프로토콜이 다름을 유의.** 막대는 위 절차(고정 정책 완주 평가),
곡선은 학습 중 로그임. 서로 다른 자로 잰 값이라 숫자를 직접 비교하면 안 됨.

## 5. 학습 곡선 y축이 뭐냐

로그에 찍히는 `R` 아님. 같은 로그의 결과 분포로 다시 계산한 값임.

```
보상 = 1.5 x 도착 − 6.0 x 충돌 − 0.5 x 시간초과      (창별 종료 에피소드 수로 가중)
```

로그 `R`은 매 결정마다 주는 유도 보상 평균이라 도착·충돌 같은 최종 결과랑 상관이 거의 없음
(실측 r ≈ 0.02). 그거 그대로 그리면 성능 그림이랑 곡선이 딴소리를 함.
위 식은 전 조건에 똑같이 적용하고, 충돌 가중치를 3~15배로 바꿔도 조건 간 순서 안 바뀜.

## 6. 그림 다시 만드는 법

| 파일 | 뭘 만드나 | 그림 |
|---|---|---|
| `make_ablation_rewards.py` | `20_REWARD/` 학습 곡선 | Fig1~6의 `0_reward_curve` |
| `build_final.py` | `99_FINAL/` 주제별 폴더 (곡선 1 + 지표 막대 6 + 상황별 1) | Fig1~Fig6 |
| `make_mixed_fleet.py` | 혼합 함대 막대 | Fig7 · Fig8 |
| `regenerate_all.py` | 곡선류를 환경변수 고정해서 순서대로 실행 | — |

**순서 지킬 것.** `build_final.py`가 `99_FINAL` 아래 png/pdf를 전부 지우고 다시 만들기 때문에,
혼합 함대를 먼저 만들면 지워짐.

```
cd Figures
python regenerate_all.py     # 곡선 (VESSEL_FIG_XMAX=15000000 여기서 주입됨)
python build_final.py        # Fig1~Fig6
python make_mixed_fleet.py   # Fig7·Fig8  ← 반드시 build_final 뒤
```

`make_ablation_rewards.py`를 직접 돌리지 말 것. x축 상한이 안 걸려서 16M까지 그려짐(0절 참고).
직접 돌려야 하면 `VESSEL_LOG_DIR=_data VESSEL_FIG_XMAX=15000000` 를 손으로 넣을 것.

전부 `Figures/_data/`에 얼려둔 로그만 읽음. 값을 손대는 코드는 없음.
`_data/`가 있으니 다른 폴더 다 지워져도 그림은 그대로 다시 나옴.
학습 결과를 새로 반영하려면 `.log` `.csv` 를 `_data/`에 복사하고 평가 한 줄을
`metrics_v2.txt` · `metrics_sit.txt` 끝에 붙이면 됨.
