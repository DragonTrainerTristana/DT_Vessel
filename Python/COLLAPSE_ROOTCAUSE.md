# 학습 붕괴 원인 규명 (2026-09-05)

2026-09-04 structfix 배치의 `off_s45` 가 무너진 건에서 출발함.
저자가 "학습 실패 시드"로 결과에서 제외했고, 선배 연구자가 그 처리를 비판함:
"N=3~5 시드는 제대로 작동하는 걸 3~5번 해보는 거지 멀쩡한 게 나올 때까지 찾는 게 아니다."
저자도 동의했고, **시드를 늘리기 전에 코드를 의심하는 쪽**으로 방향을 잡아 이 조사를 함.

## 0. 결론

붕괴 = **ControlActor 의 RadarEncoder 가 dying ReLU 로 죽어 정책이 레이더를 못 보게 되는 것**임.

- 시드 운이 아니고, 확률적으로 일어나는 최적화 사건임. **실측 발생률 3/80 = 3.75%** (OFF 팔, 기준 A).
- 장애물을 알려주는 채널이 레이더뿐이라 **장애물 충돌로 터짐**(oColl 57~74%).
- critic 의 레이더 인코더는 멀쩡함 → "정책만 눈이 멀고 가치함수는 봄".
- 검토한 다른 원인(GAE 절단 버그 · 진행보상 계수 · StateRecon 러닝통계)은 **전부 A/B 로 기각**.
- **LeakyReLU 로 바꾸면 0/80 (p=0.047)** — 완화책은 찾았음(5절). 다만 기본값은 안 바꿨음.

## 1. 증거

`m2_S_off_s45` (붕괴) vs `m2_S_off_s43/44` (정상), 전부 같은 배치·같은 설정.

### 1-1. 가중치가 얼어 있음

`ctr_actor` 레이더 인코더 파라미터의 step2M → step6M 절대변화량 합:

| 런 | ctr_actor 레이더 | critic 레이더 |
|---|---|---|
| off_s43 | 1655.6 | 2174.5 |
| off_s44 | 2154.1 | 1953.0 |
| **off_s45** | **0.000000** | 2105.4 |

같은 런 안에서 critic 은 정상 학습됨. **정책 쪽에만 gradient 가 0.**

### 1-2. Adam 모멘트가 gradient=0 을 증언

`exp_avg` 가 float32 최소 비정규수(5.6e-45), `exp_avg_sq` 는 β₂ 지수감쇠만 함
(관측 감쇠비 0.146/1M ≈ 이론값 0.999^3906 = 0.141).

### 1-3. 행동 반사실이 정확히 0

레이더 입력을 통째로 "무장애"로 바꿨을 때 `|Δaction|`:

| 런 | Δaction |
|---|---|
| off_s43 | 0.0113 |
| off_s44 | 0.0057 |
| **off_s45** | **0.000000** |

정면 ±15° 에 8m 장애물을 심어도 off_s45 는 Δrudder 0.00000 · Δthrust 0.00000.
off_s43 은 Δrudder −0.319 · Δthrust −0.918 (급감속).

### 1-4. 널정책과 구분이 안 됨

| 정책 | goal | vColl | oColl |
|---|---|---|---|
| 무조타 직진 | 0.5% | 30.9% | 68.6% |
| 목표방위 P제어(장애물 무시) | 8.1% | 27.2% | 64.7% |
| **off_s45 @16.06M** | **9.4%** | **33.6%** | **56.6%** |
| off_s43 @16.06M (같은 기하) | 93.6% | 0.8% | 0.1% |

### 1-5. 단독 사고가 아님

같은 지문 3건: `m2_S_off_s45` · `m2_F1base_s42`(ON 팔, step1M 에 이미 죽음) · `tb_s46`.
신 시대 34런 중 3건 = 9%.

## 2. 기각된 원인 (전부 A/B 실험)

2.5M · 128envs · 16vessels · OFF 팔. 판정 문턱은 **결과 보기 전에 고정**했음.
⚠️아래 표는 처음 쓴 기준(최종 oColl>20 또는 goal<20)임. 나중에 이 기준이 실행 길이에 오염된다는 걸
알게 돼 5절에서 기준 A(최소 에피소드 길이)로 바꿨음. 그 기준으로 다시 세면 `pg1_s46`은
붕괴가 아니라 **탈출이 느렸을 뿐**(최종 oColl 1%)이라 빠짐 → ReLU 누적 4/80 → **3/80**.

| 조건 | 붕괴 | 평균 goal |
|---|---|---|
| base (기존 그대로) | 0/8 | 63.8 |
| `VESSEL_TIMEOUT_BOOTSTRAP=1` (GAE 절단 수정) | 1/8 | 52.2 |
| `VESSEL_PROGRESS_COEF=1.0` (진행보상 1/3) | 1/8 | 57.4 |
| 둘 다 | 0/8 | 61.2 |
| `VESSEL_RECON_LEGACY_STAT=1` (StateRecon 버그 동작) | 1/16 | 56.9 |
| StateRecon 수정본 | 1/16 | 57.0 |
| ReLU 기본 (4파 대조) | 0/16 | 57.9 |

**ReLU 계열 누적 3/80 = 3.75%**(기준 A). 조건 간 차이 없음 — 어느 스위치도 붕괴를 못 줄임.

### 2-1. 보상 EV 가설이 왜 틀렸나

γ=0.99 에 에피소드가 400~1100결정이라 **종말 보상이 감가로 거의 사라지는 건 사실**임:

| 항 | 원값 | 감가 후 |
|---|---|---|
| 도착 @942결정 | +150 | +0.012 |
| 충돌 @433결정 | −300 | −3.87 |

에피소드 가치를 dense shaping 이 전적으로 결정하고,
결정당 shaping gross 가 도착 +1.737 vs 장애물충돌 +1.736 으로 **사실상 동일**함.
그런데도 진행보상 계수를 1/3 로 줄여도 붕괴율이 안 변함 → **이건 붕괴 원인이 아님.**
(다만 "shaping 이 결과를 압도한다"는 사실 자체는 남는 별개 사안임.)

| | 값 |

| 붕괴 런 | 587 · 607 (신 시대 3건은 593~662) |
| 정상 런 | 851 ~ 3641 |

## 4. 넣은 것 (전부 기본값 불변)

| 스위치 | 기본 | 무엇 |
|---|---|---|
| (자동) 붕괴 검출기 | 항상 켬 | ControlActor 레이더 인코더 gradient 가 N회 연속 0 이면 학습 중 경고. `VESSEL_BLIND_WARN_AFTER`(기본 200) |
| `VESSEL_RADAR_ACT=leaky` | `relu` | RadarEncoder 의 ReLU 4겹을 LeakyReLU(0.01) 로. 음수쪽 기울기를 남겨 흡수상태 제거 |
| `VESSEL_PROGRESS_COEF` | `3.0` | 진행(shaping) 보상 계수 |
| `VESSEL_TIMEOUT_BOOTSTRAP` | `0` | timeout 을 절단으로 처리(GAE) |
| `VESSEL_RECON_LEGACY_STAT` | `0` | StateRecon 러닝통계 수정 전 동작 |

활성함수 교체·보상 계수 변경은 **설계 변경이라 기본값을 바꾸지 않았음.** 저자 승인 사항.

## 5. LeakyReLU 완화 — 결론

**총 160런(ReLU 80 / LeakyReLU 80)으로 판정 완료.**

| 활성함수 | 붕괴 | minlen 최소 | 1분위 | 중앙 |
|---|---|---|---|---|
| ReLU (7조건 누적) | **3/80 = 3.75%** | 569 | 1489 | 1672 |
| LeakyReLU(0.01) | **0/80 = 0.00%** | 1067 | 1781 | 2149 |

이항검정: ReLU 기저율 3.75% 하에서 leaky 80런 중 0건일 확률 = **p = 0.047**.
프로토콜 일치 부분집합(2.5M 완주)만 봐도 ReLU 3/80 vs Leaky 0/32 로 방향 동일.

**LeakyReLU 가 붕괴를 없앤다고 볼 근거가 있음.**
붕괴 건수뿐 아니라 minlen 분포 전체가 밀림(최소 569 → 1067, 붕괴 문턱 700 에 아무도 근접 안 함).

### 판정 기준을 도중에 고친 이력 (기록용)

처음 쓴 기준(최종 oColl>20 또는 goal<20)이 **실행 길이에 오염**됨을 발견함.
모든 런이 0.66M 부근 장애물충돌 스파이크를 거쳐 시간초과 고원을 탈출하는데,
2.1M 에서 자르면 그 전환 중간값이 최종값으로 찍혀 48건이 오탐으로 잡혔음.
기준 A(0.6~2.0M 최소 에피소드 길이)는 창이 2.0M 안에 닫혀 실행 길이와 무관함.
이 정정으로 ReLU 붕괴율도 4/80 → 3/80 으로 바뀜(`pg1_s46` 은 탈출이 느렸을 뿐, 최종 oColl 1%).

### 그래도 남는 한계

- OFF 팔 · 2.1~2.5M · 이 기하에서만 잰 값임. ON 팔과 16M 수렴은 미측정.
- LeakyReLU 가 **왜** 듣는지는 기전 가설(음수쪽 기울기로 흡수상태 제거)까지만이고 직접 확인 안 함.
- 활성함수 교체는 신경망 설계 변경이라 **기본값은 `relu` 그대로 둠.** 채택은 저자 결정.

## 6. 재현

```bash
# 붕괴 지문 확인 (체크포인트 필요)
python - <<'PY'
import torch, os
B = '<체크포인트 폴더>'
def sd(n, m): return torch.load(os.path.join(B, f'{n}.step{m}M.pt'), map_location='cpu')['model_state_dict']
for n in ('m2_S_off_s43', 'm2_S_off_s45'):
    a, b = sd(n, 2), sd(n, 6)
    for pref in ('ctr_actor.experts.0.radar_encoder', 'critic.experts.0.radar_encoder'):
        ks = [k for k in a if k.startswith(pref) and a[k].dtype.is_floating_point]
        print(n, pref, sum(float((a[k]-b[k]).abs().sum()) for k in ks))
PY

# 붕괴율 재측정 (8병렬 기준 16런 ~30분)
```
