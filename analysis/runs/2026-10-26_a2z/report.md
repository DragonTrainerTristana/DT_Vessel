## 2. 문제 A–Z (층별 트리)

ROOT = 고쳐야 목표에 닿는 원인. DOWNSTREAM = ROOT 를 고치면 같이 사라질 증상.

```
L1 OFF 학습 실패 ─┬─ L1-2 표본 잡음(수준)      ← L3-1 엔트로피·squash, 침로 눈금

                  └─ L3-3 PPO 자기 보상 퇴화(f2_ 만 확인)
L4·L6 측정·판정 [ROOT: 판정] ── 표본 행동·1시드·끝점·판정식·관문 기준
L6-1 목표 문언 [ROOT: 목표] ── 규칙 배 상한으로도 불가
L7 과정 [ROOT: 과정] ── 다요인 동시 변경·override·결정 대기
DOWNSTREAM: 곡선 V/M 불통과, trunk 관문 실패, qb_ comm 0/6, H1a 위반 4회, 통신 팔 연료·방향 열세(일부)
```

- 효과가 고정이어도 n 이 커지면 통과 확률이 떨어짐(재현: 효과 17.3 에서 n=1 0.75 → n=3 0.31 → n=10 0.005)
- 1시드·offb 없음이면 Woerner·연료는 N=0 → 효과 0 이어도 약 50 % 통과. 도착·vColl·DCPA 는 최선 OFF 풀 조건이 따로 막음
- 충돌 하한 12.1 은 09-28 옛 보상 재학습에서 잰 값임
- f2_ 는 3/3 우세 3개가 OFF 범위 때문에 불통과함
- 정정: '완벽한 통신도 충돌은 원리상 통과 불가'는 틀림(col300ih−col56h −19.8 > 12.1)
- 검증: 확인(measure-02), 개연(design-03 정정)

**L6-3 관문 기준이 자명한 기준선과 안 맞음**
- trunk 관문 30 % < goal 배 50.3 → 통과가 유능함을 뜻하지 않음. s_·qb_ 는 통과 뒤 갈래가 35.5 % 로 끝남
- P0(80/15)는 표본 행동으로 잼
- 검증: 확인(timeline-16·design-11)

**L6-4 G1(OFF 유능)·G2 가 09-24 에 불통과(`plan.html:169-170`)했는데 '보고'로만 남음**
- 이후 모든 비교는 goal 배 수준 학습 OFF 상대임
- 같은 정보의 더 강한 OFF(vo56)는 비교에서 빠짐
- 검증: 확인(timeline-03 정정)

**L6-5 주장 범위에 따라 헤드룸이 달라짐**
- '최선 OFF 대비 안전': VO 쌍 vo300i−vo56h150 은 도착 +3.3·충돌 −3.5
- '준수하면서 안전': col 쌍 +20.0/−19.8
- 3.5 pt 는 '정보 상한'이 아니라 규칙 배 한 쌍의 차이일 뿐임
- 검증: 개연(design-17)

**L6-6 'latent ≈ 전부'를 비교할 대상이 없음**
- 기술적으로는 같은 trunk 에서 참값 필드 갈래가 가능함(x_oni6·t_ decode 선례). 지금 설계가 안 돌릴 뿐임
- 검증: 개연(design-10 정정)

**L6-7 (미검증 minor)**
- H1a '나쁘면 버그'는 현 잡음에서 검정 불가(design-18)
- LR 감쇠 아래 분기 입력 전환이 comm 에 불리(design-19)

### L7. 과정

**L7-1 [ROOT·과정] 배치마다 여러 요인을 동시에 바꿈**
- f_: 행동 모드·OFF 입력·K·메시지·흉내·선생님
- n_: 흉내 제거 + R1 + R2
- qb_: 토글 2개 동시 → 원인 귀속 불가
- 검증: 확인(timeline-09)

**L7-2 사후 override·절제 생략·지표 교체**
- 결과를 본 뒤 관문을 넘긴 것 2회: P0 10-06, 순위 v4 10-09. q_ 는 사전에 정한 재사용이라 사후 override 아님
- t_ 정지 조건 해제·절제 생략, s_ 빠른 ablate 대체, Woerner·R8 교체, 10-07 '300 m 유지'를 10-13 에 번복
- 검증: 확인(timeline-10), 개연(design-13 정정)

**L7-3 결정 대기가 계산 시간보다 김**
- 계산: trunk 75–92분, phase1 약 3.5 h
- 대기: n_→q_ 4일, qb_ 이후 13일
- 검증: 개연(design-14)

**L7-4 '시드 1개 먼저' + offb 제거로 잡음 자가 없음**
- trunk 단계는 GPU 병렬이라 벽시계가 같음
- 갈래 단계는 공유 GPU 때문에 늘어남(f2_ phase1 약 11 h)
- 검증: 개연(design-15 정정)

**L7-5 학습 없이 가를 수 있는 가설이 쌓인 채 새 학습이 먼저 돎**
- 예: n_ 평균 행동 epReward 상승 + 표본 하락 자료가 이미 `diag_trunk_n` 에 있었는데 해석 안 됨
- 검증: 확인(timeline-21)

**L7-6 기본 sanity·하이퍼파라미터 탐색 없음**
- 작은 장면(2–4척) 실험 흔적 없음, PPO 상수 고정
- 10-13 스펙 금지 목록이 탐색을 막음
- agile·옛 보상·타각 모드에서는 같은 학습기가 98–99 % 였음
- 검증: 개연(timeline-17)

**L7-7 (minor) 인프라 불안정**
- GPU 정지·TDR·재부팅·다른 계정 점유(timeline-22)

## 5. How to analyze — 상위 분석 절차

### 5-1. A7 평균 행동 평가 (판단 대부분이 여기서 갈림)

- 도구: `PY/runs_fig1/2026-10-02_fig1/eval_mean.py`(진단 전용). `diag_trunk.sh` 가 n_ 에 쓴 방식을 그대로 따름
- env 는 학습과 같게 둠
  - off·trunk 는 ARPA 설정, comm 은 comm 설정
  - `ckpt_io.restore_policy`·`make_env_from_snapshot` 경유. `VESSEL_*` 직접 세팅 금지
- 인자(measure-01 제안): `--envs 256 --eval_decisions 3000 --burnin 2400 --drain 4500 --seed 999`. 실제 인자명은 스크립트 헤더로 확인
- 같은 체크포인트를 표본(eval_ckpt)으로도 같은 조건에서 잼. 이미 있는 곡선 값은 drain 3000 이라 조건이 다름
- 표본 크기
  - 3000 결정 × 256 env × 16척이면 완료 에피소드 약 5–10k → 이항 SE 약 0.5 pt
  - 체크포인트 간 SD 16 pt 이므로 팔 비교는 **체크포인트 3–4개 평균**으로 함
- 산출 표: 런 × 체크포인트 × {평균, 표본} × {도착, vColl, epReward, 무조우 오프셋, 첫 변침, pair_enc(같은 길이 기준)}
- 흘러가는 결정
  - H1(평균−표본 ≥ 15 pt?)
  - H2(epReward↑·도착↓ 동시?)
  - H4(qa_ ≥ 75 / ≤ 60)
  - H10(qb_ 4점 평균 부호)
  - → C1·C5
- 함정: 미완 에피소드 수가 평균과 표본에서 다름(689 vs 1229 결정). drain 4500 으로 맞추고 [censored] 줄은 b1 전까지 믿지 않음

### 5-2. A9 logstd 덮어쓰기 스윕

- 새 스크립트(평가 전용, 스크래치 또는 runs 폴더): eval_mean.py 와 같은 흐름
  - restore 뒤 `ctr_actor.experts.k.action_logstd[0]` 을 고정값으로 덮어씀
  - `dist.sample()` 경로로 평가함
- 입력: n_·qb_ 9.04M, logstd 값 5개
- 출력: 도착·epReward·결정당 |침로오차|>10° 비율·타 이동량/결정
- 해석
  - logstd ≥ −1 에서 지표가 평평하면 σ 고원 확정 → C5(ii)(iii) 근거
  - −2.3 에서 표본이 평균 행동에 근접하면 '수준 = 잡음' 재확인

### 5-3. A1·A2 잡음 자와 추정량 (Mac, python3 표준 라이브러리)

## 6. 하지 말 것 / 함정 (증거에서 나온 것)

- **결과 본 뒤 관문·판정 기준을 바꾸지 않음.** 바꾸려면 다음 배치 사전등록으로만 함(L7-2)
- **1시드 단독 주장 금지.** 재분기만으로 20 pt 흔들림. 평균에는 시드별 승패를 같이 적음
- **보상 버전이 다른 배치끼리 epReward·결정당 R 을 비교하지 않음**(v3 / v3+R1R2 / 단계 2 는 서로 비교 불가)
- **표본 행동 학습 배와 결정론 규칙 배를 그대로 비교하지 않음**(qa_ 47.1 vs vo300 94.3 같은 비교)
- **학습 창 초반(≈1.3–2.3M) 값과 '최고 창' 값을 정책 최고점으로 쓰지 않음.** 첫 창 R 은 에피소드 시작 구간만 담음
- **끝 체크포인트 한 점으로 팔 순서를 확정하지 않음**(qb_ 4점 중 2:2)
- **최선 OFF 풀에 설정이 다른 배치(t_off)를 섞지 않음**
- **규칙 배 한 쌍의 차(3.5 pt)를 '정보 상한'이라 부르지 않음**
- **시드 1 만 골라 인용하지 않음**(G 차 +7.3 vs 3시드 +28)
- **코덱 복원 충실도를 의사결정 유용성으로 읽지 않음.** 레이더 30칸은 전달도 안 됨
- **Woerner 단독으로 COLREGs 개선을 주장하지 않음**(충돌 42 % 배가 최고점)
- **`pair_enc_per_ship_ep` 와 관문 judged/ep 를 섞지 않음**(단위가 다름)
- **실행 이름으로 구조를 판단하지 않음.** `_batch_env.txt`·스냅샷·로그 헤더로 확인함
- **D 진단 logstd '전문가 평균'으로 판단하지 않음.** None 전문가를 따로 봄
- **두 토글을 한 배치에 같이 켜지 않음**(qb_ 의 logstd·LR)
- **무거운 평가·학습을 Mac 에서 돌리지 않음.** Mac 은 읽기·가벼운 파싱만
- **H1a 위반을 1시드 결과로 버그로 단정하거나 무시하지 않음.** 절제·평균 행동으로 먼저 가름
- 옛 PDF 의 코드 줄 번호(예: 정면조우 PDF 의 `vessel_gym.py:705·727`)는 현 b6a4341 과 다름
